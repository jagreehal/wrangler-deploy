fix(init): `wd init --preset monorepo` discovers existing workers instead of emitting placeholders

Following the documented `wd init --preset monorepo` example on a repo that already had `wrangler.jsonc` files produced a scaffold with placeholder worker paths (`apps/api`, `apps/worker`) that had to be hand-edited. The monorepo preset now prefers real discovery — the same scan plain `wd init` uses — and falls back to the placeholder skeleton only for a greenfield repo with no configs yet.
